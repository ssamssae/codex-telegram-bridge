# Interface languages and verification

[English README](../README.md) · [한국어 시작 안내](../README.ko.md)

The local catalog supports `en` and `ko`. There are no translation requests,
credentials, additional packages or changes to the user's Codex model.

## Selection and persistence

- In the configured Telegram chat, use `/language en`, `/language ko`, or
  `/language` to inspect the current selection. Commands are consumed by the
  bridge and are never sent to Codex. The existing chat allowlist still applies.
- A saved selection in `bridge-language.json` under the bridge state directory
  takes precedence over `CRB_LANGUAGE`, then `TAB_LANGUAGE`, then the default.
  Both backends use the same precedence; the saved file has private permissions.
- The public package defaults to English. Internal source installations retain
  their Korean default. Regional environment values such as `ko-KR` and `en_US`
  normalize to their base language; unsupported environment values fall back
  to the installation default. `/language` accepts only `en` and `ko`.
- A corrupt or unreadable saved file falls back safely. A failed save leaves the
  previous in-memory selection unchanged and reports failure.
- `setup --language ko` sets the initial `TAB_LANGUAGE` in the private config;
  rerunning setup does not erase an existing in-chat selection.

## Boundaries

Localized surfaces include connection replies, bridge error wrappers, approval
and selection card instructions, async question cards, recovery controls and
submission notices. Actual prompts, options, commands, reasons, answers, code,
paths and underlying tool diagnostics are passed through unchanged. In-flight
cards are not proactively edited when the language changes; future renders use
the selected language. Existing callbacks keep their protocol values.

Terminal setup/doctor diagnostics and advanced operator progress/flow reports
retain their existing wording. The Korean README covers installation and core
use; advanced reference documentation remains in English.

## Verification paths

Prerequisites: an installed package and its one configured, allowlisted chat.
Real messages require the operator's authorization; unit tests use temporary
state and fake Telegram/terminal clients.

| Entry and operation | Expected result | Automated evidence |
| --- | --- | --- |
| `/language ko`, restart, `/language` | Korean is still selected | `tests/test_bridge_i18n.py` persistence test |
| `/language en`, `/ping` | English connection reply, no Codex input | REPL and exec command tests |
| `/language ja` | Usage help; saved selection unchanged | Unsupported-locale test |
| Same command from another chat | Ignored, no state write | Chat allowlist test |
| Approval/async question card | Localized instructions, original question/options and callback values | Card rendering tests |
| A Codex answer that resembles a catalog message | Relayed unchanged | Answer-preservation test |
| Unwritable language state | Failure notice; previous language retained | Atomic-save failure test |
| Public export / installed package | Locale module and tests included, setup flag accepted | Export suite and package smoke checks |

These are local, simulated boundaries. No live Telegram send, service restart,
or production deployment is implied by a passing unit or export test.
